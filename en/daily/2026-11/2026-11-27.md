## High-signal developments

### 1. OpenAI corrects GPT‑6.2 subscription usage accounting

- **What happened:** On November 26, OpenAI's Thibault Sottiaux said on X that most users had incorrectly discounted GPT‑6.2 Astra and Sol usage at launch. After correction, users will hit their limits about 40% faster on Astra and 25% faster on Sol than in the preceding week. Past usage will not be charged retroactively, and Go, Plus, Pro and Business users receive a one-time banked reset.
- **Why it matters / lens:** Product decisions and investment monitoring. Subscription products need clear task-cost and allowance changes. The percentages compare time to reaching limits, not API price increases.
- **Publication / type / original source:** November 26, 2026, [OpenAI employee's original post](https://x.com/thsottiaux/status/2125784147889393806), public company-staff statement; [TechRadar coverage](https://www.techradar.com/ai-platforms-assistants/chatgpt/weve-fixed-this-now-so-the-same-work-will-use-more-of-your-plans-usage-allowance-openai-admits-it-made-a-mistake-when-launching-gpt-6-2-and-now-paying-chatgpt-users-could-hit-their-usage-limits-up-to-40-percent-faster), media relay.
- **Corroboration / confidence:** The article quotes the original post and is not an independent billing audit. High confidence in the correction statement; actual user impact still needs account-level checks.
- **Trend:** T01/T03, continuing rise; focus moves from model sticker price to complete-task allowance.

### 2. NVIDIA expands Nemotron 3.5 Parse data and inference tooling

- **What happened:** NVIDIA published three synthetic datasets: about 9.98 million chart examples, 1 million table examples and 7.9 million multilingual OCR pages, plus a fine-tuning recipe and DFlash2 speculative decoding. On one H200 under specified conditions, it reports 7.62× throughput at low concurrency and 1.52× at high concurrency versus the same model with speculation disabled.
- **Why it matters / lens:** Product decisions and technical context. Document agents can validate layout, tables and charts separately; adapting synthetic data requires error analysis on real enterprise files.
- **Publication / type / original source:** November 26, 2026, NVIDIA [Hugging Face technical article and dataset links](https://huggingface.co/blog/nvidia/building-on-nemotron-35-parse-open-data-fine-tunin), company technical material.
- **Corroboration / confidence:** Data and recipe are inspectable. Throughput and quality are team benchmarks, not evidence for other hardware or real documents. High confidence in release; performance extrapolation unverified.
- **Trend:** T01/T04, continuing rise; model delivery now includes training data and inference stack.

### 3. llama.cpp and AMD publish an inspectable local-inference dashboard

- **What happened:** ggml-org released a Hugging Face dashboard for AMD Ryzen/Radeon showing 512-token prompt processing, 128-token generation and context-scaling results by hardware, model, quantization and build. Underlying results and workflows are public. Current hardware includes Radeon 8060S and Radeon AI Pro R9700S.
- **Why it matters / lens:** Product decisions and technical context. Local deployment choices require more than one tokens-per-second figure: long context, memory, power and task quality also matter.
- **Publication / type / original source:** November 26, 2026, [ggml-org/Hugging Face article](https://huggingface.co/blog/ggml-org/llamacpp-amd-bench), project technical release.
- **Corroboration / confidence:** Dashboard and raw results are inspectable. Hardware and workload scope is limited; this is not an independent cross-hardware league table. High confidence in delivery, limited generality.
- **Trend:** T03, continuing rise; inference-hardware comparisons move toward public workloads.

### 4. Hugging Face publishes a multi-agent training tutorial

- **What happened:** The first article in a Hugging Face series demonstrates communication training with four agents, a shared language model and a verifiable task. It notes that adding agents changes context and budget. Complex cases cited from other teams are not results from this tutorial.
- **Why it matters / lens:** Product decisions and technical context. Compare multi-agent systems with one agent on identical tasks and budgets, using success, latency and cost.
- **Publication / type / original source:** November 26, 2026, Hugging Face [tutorial](https://huggingface.co/blog/training-swarms), project method note.
- **Corroboration / confidence:** The example is reproducible. General gains from large agent systems remain a methodological hypothesis. High confidence in the tutorial; benefits unproven.
- **Trend:** T04/T07, continuing rise; agent count becomes a design variable to test.

### 5. Alibaba Cloud lists a structured decision model (catch-up)

- **What happened:** Model Studio's November 25 release notes list `decision-model`, describing text, image or business-context inputs and classification, binary decisions or score distributions with confidence values. Suggested uses include ticket routing, content moderation and agent routing.
- **Why it matters / lens:** Product decisions and editorial planning. A specialized decision model might reduce the cost of using a general chat model for high-frequency routing; calibration, error rates and regional availability need testing.
- **Publication / type / original source:** November 25, 2026, Alibaba Cloud [Model Studio release notes](https://docs.modelstudio.console.alibabacloud.com/en/model-studio/newly-released-models), official product documentation; catch-up.
- **Corroboration / confidence:** Access entry is checkable; effectiveness and pricing lack independent tests. High confidence in publication; business value unverified.
- **Trend:** T01/T04, first catch-up; model supply continues to specialize by task.
